# NATSKit v0.1.0 — first standalone release

**Release status: APPROVED, NOT YET TAGGED/PUBLISHED.** Use these notes when creating the v0.1.0 GitHub Release.

## Overview

NATSKit is an application-agnostic Go module for NATS Core and JetStream transport, configuration, verified topology, managed additive reconciliation and shared pull Durable workers. It does not depend on CRA Bridge, application databases, domain models, Protobuf contracts or application loggers.

- Module: `github.com/majiddarvishan/natskit`
- Go requirement: `1.26.0` or later
- First pre-1.0 API release; callers must review future changes for compatibility.

## Included capabilities

- Strict JSON configuration and offline `Config.Resolve`; alias-based subjects, profile/default inheritance, optional TLS and NATS credentials.
- `Connect` is read-only for broker topology; Core NATS is supported without JetStream.
- Explicit `ConnectReconciled` / `Reconcile`: complete preflight, creation of missing Streams/Consumers, **additive** Stream subject expansion and post-change verification. Incompatible policy, Durable filter or removed/replaced subject changes fail closed with structured `ReconcileBlocked` diagnostics. No delete, purge, data reset or implicit cursor migration.
- Publish with JetStream PubAck and caller-provided stable message IDs; generic multi-replica pull workers with explicit ACK, application-configurable retry/quarantine options and observability without body logging.
- Quarantine ACK safety: require destination PubAck before source ACK. Applications own business idempotency and DB commit-before-ACK.
- Standalone disposable localhost NATS tests include shared Durable, retry, quarantine failure, reconnect and three-node leader-failover scenarios.

## Operational limitations

- **At-least-once** processing: no exactly-once business operations or transaction management.
- No automatic lossless replacement of Stream subjects, Durable filter migration, ACK cursor conversion, replay, or data recovery. Such drift intentionally blocks managed startup until a separately coordinated operator-approved cutover.
- MaxDeliver advisories are best-effort; no guaranteed automatic exhausted-message reconciliation.
- Quarantine may contain sensitive payloads; operators must enforce suitable ACLs, retention, quotas and privacy safeguards.
- Tested disposable failure scenarios do not establish all-case reconnect/HA, production readiness, disaster recovery or SLO guarantees.
- No CRA Bridge merge, live NATS/PostgreSQL action or customer deployment is part of this release.
